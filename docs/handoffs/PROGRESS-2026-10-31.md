## 已实现

| 端点 | 鉴权 | 行为 |
|---|---|---|
| `GET /v1/meta` | 免鉴权 | 返回 apiVersion、能力集、上限 |
| `GET /v1/updates` | 渠道令牌 | 游标流 + 长轮询；`wakeup` 按是否 @ 成员判定 |
| `POST /v1/messages` | 渠道令牌 | 发消息，`clientMsgId` 幂等 |
| `POST /v1/updates/ack` | 渠道令牌 | 推进游标（按渠道 × 会话存） |
| `GET /v1/quota` | 渠道令牌 | 待处理数与上限 |
| `POST /api/admin/channels` | 主人 | 建渠道，**明文 token 只返回一次** |
| `GET /api/admin/channels?member=` | 主人 | 列渠道（不含 token） |
| `DELETE /api/admin/channels/{id}` | 主人 | 吊销 |

配套：

- 迁移框架 `src/migrations.js`：`PRAGMA user_version` + 顺序迁移（v1 baseline / v2 channels / v3 channel_cursors）；
- 渠道模型 `src/channels.js`：一 token = 一成员，库里只存 sha256；
- 鉴权 `src/http/auth.js`：`Authorization: Bearer cf_…`，与 owner cookie、member 双头并存；
- 路由 `/v1/*` 纳入 API 分支，不再落静态资源。

## 怎么用（curl）

```bash
# 1) 主人登录拿 cookie
curl -c /tmp/cf.txt -X POST http://127.0.0.1:8099/api/login -d '{"password":"<主人口令>"}' -H 'Content-Type: application/json'

# 2) 给成员建渠道（token 只出现这一次）
curl -b /tmp/cf.txt -X POST http://127.0.0.1:8099/api/admin/channels \
  -H 'Content-Type: application/json' -d '{"member":"ruyi","name":"如意群聊"}'

# 3) 拉更新（长轮询 25 秒）
curl "http://127.0.0.1:8099/v1/updates?chat=main&wait=25" \
  -H "Authorization: Bearer cf_xxx"

# 4) 回复
curl -X POST http://127.0.0.1:8099/v1/messages \
  -H "Authorization: Bearer cf_xxx" -H 'Content-Type: application/json' \
  -d '{"chatId":"main","text":"收到","clientMsgId":"m-1"}'

# 5) 确认
curl -X POST http://127.0.0.1:8099/v1/updates/ack \
  -H "Authorization: Bearer cf_xxx" -H 'Content-Type: application/json' \
  -d '{"chat":"main","cursor":42}'
```

## 2. Review 发现并修掉的问题（M4）

| 严重度 | 问题 | 修法 |
|---|---|---|
| **高** | 同会话并发投递会互相覆盖：`waits` 按 sessionId 单槽，而默认 1:1 模式下多个群的 poller 并发投进同一会话，后者顶掉前者的 waiter → 前一条回复丢失 | `dsh-host.js` 加 promise 链，同 sessionId 的 `ask/inject` 串行 |
| 中 | 错误信封读死：客户端只认 `{error:{code,message}}`，围炉实际是扁平 `{error, code}` → `cursor_expired` 被读成 `http_400`，自动重拉失效 | `campfire-client.js` 两种形状都认 |
| 低 | update 缺 `chatTitle`，插件来源标记退化成 chatId | `/v1/updates` 补字段 |

## 3. 长轮询改事件驱动（原 300ms 轮询）

- `EventHub.wait(chatId, timeoutMs, signal)`：匹配变化 / 超时 / 中止三者之一即返回，`emit` 时唤醒；
- `/v1/updates` 不再定时轮询：**空闲零唤醒，有消息立刻返回**，客户端断开按 `req.close` 提前收尾；
- `closeAll` 一并收尾等待者，不留悬挂 Promise；
- 回归测试：C21「挂起期间有新消息立刻唤醒」。

## 5. mock 对齐 + `--strict`

- 出站消息改为进同一条流（原来 `broadcast:false`），并补 `pump()` 唤醒挂起的轮询——
  **这条原本是 mock 的真 bug**：拿它验收「长轮询」根本验不出来；
- meta 补 `limits`；幂等命中改 200 + `duplicate:true`；超长文本 400；
- 新增 `--strict`：错误体扁平、chatId 必填、只能碰自己的会话、非法 cursor 400、不带 cursor 用已确认位置；
- 默认仍是宽松模式（M4 单测断言的是宽松行为），要验契约用 `--strict`。
