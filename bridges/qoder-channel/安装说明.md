# 围炉 × Qoder 渠道插件 · 安装说明

> 版本：0.1.0
> 打包文件：`campfire-channel-0.1.0.zip`

---

## 这个插件做什么

把**围炉群聊**接进 Qoder：

```
群里 @你的成员
   ↓
Qoder 自动创建/继续一个真实会话（界面可见）
   ↓
模型回复
   ↓
回复自动回到群里
```

**不需要**：装 Node、开调试端口、跑外接程序、碰你的 Qoder 登录态。

---

## 前置条件

1. **Qoder CN 桌面端**已安装并登录
2. **围炉**已在跑（NAS 或本机），且能从这台电脑访问
3. 围炉里已有一个**成员**（handle 自己定，比如 `qoder`），并**已加入目标群**

---

## 第一步：在围炉里准备成员和令牌

1. 打开围炉网页（如 `http://<NAS_IP>:8099`）
2. 进入**成员管理** → 新建成员
   - handle：`qoder`（或你喜欢的）
   - 显示名：`Qoder`
   - 驱动：`pull`
3. **让成员加入群**（否则收不到消息）
4. 进入**接入设置** → **生成渠道令牌**
   - 得到类似 `cf_xxxxxxxxxxxxxxxx` 的字符串
   - **复制保存好，只显示一次**

---

## 第二步：在 Qoder 里安装插件

1. 打开 Qoder → **扩展管理**（左侧或设置里）
2. 右上角点 **`+`**（或「导入/安装插件」）
3. 选择 **`campfire-channel-0.1.0.zip`**
4. 安装完成后，在插件列表里找到 **「围炉 Campfire」**

> **如果显示「已禁用」**：点它的开关手动启用。如果开关点不动，说明这个插件被判定为「来源不可信」——见文末「已知限制」。

---

## 第三步：配置围炉地址和令牌

1. 在插件列表里点 **「围炉 Campfire」**（或它的「设置」）
2. 找到**插件配置**入口（`qoder.communication` 提供）
3. 填写：
   - **围炉地址**：`http://<NAS_IP>:8099`（按你实际地址）
   - **渠道令牌**：第一步拿到的 `cf_` 开头字符串
   - **成员名**：`qoder`（和围炉里的 handle 一致）
4. 保存

> **如果找不到配置界面**：手工写配置文件
> 路径：`C:\Users\<你的用户名>\.qoder-cn\plugins\data\campfire-channel-<来源>\config.json`
> 内容：
> ```json
> {
>   "baseUrl": "http://<NAS_IP>:8099",
>   "token": "cf_你的令牌",
>   "member": "qoder"
> }
> ```

---

## 第四步：验证

1. **重启 Qoder**（或点扩展页的「重新加载」）
2. 在围炉群里发：`@qoder 你好，报个到`
3. **期望结果**：
   - Qoder 里自动出现一个标题含「围炉 · qoder」的会话
   - 会话里有你发的那句话
   - 模型回复后，**回复出现在围炉群里**
   - 全程 **2~5 秒**

## 常见问题

### 群里 @ 没反应

| 检查项 | 怎么做 |
|---|---|
| 成员加入群了吗 | 围炉成员管理里看 `chats` 是否包含该群 |
| 地址通不通 | 浏览器打开 `<地址>/api/health`，应返回 `{"ok":true}` |
| 令牌对不对 | 用 `curl -H "Authorization: Bearer cf_xxx" <地址>/v1/updates` 应返回 200 |
| worker 起来没 | 任务管理器搜 `node.exe`，命令行应含 `worker.mjs` |

### Qoder 里看不到「围炉」渠道

- 确认插件在扩展管理里**已启用**（不是已禁用）
- 看 Qoder 日志：`%APPDATA%\com.qodercn.app.stable\logs\<最新>\main.log`
- 搜 `campfire`，看有没有 `CHANNEL_` 开头的错误码

### 会话创建了但不回复

- 看 worker 的 stderr（Qoder 日志里 `qoder.communication` 段）
- 常见：`CHANNEL_SESSION_ACCESS_DENIED`（会话不属于本渠道）

## 已知限制（重要，请先读）

### 1. 这个插件能不能真正当「渠道」生效，取决于 Qoder 的插件来源判定

`qoder.communication` 的渠道发现逻辑里有这一行（`server.cjs:21331`）：

```js
if (item.pluginId.endsWith("@local")) continue;
```

**本地安装的插件（`@local`）会被跳过，不会成为渠道。**

这意味着：
- **用 ZIP 本地安装 → pluginId 是 `campfire-channel@local` → 渠道不会被发现**
- **只有从 Qoder 市场安装（`@qoder-marketplace`）才能成为渠道**

**所以这个 ZIP 装上去之后，很可能只作为一个普通插件存在（有 Skill、有 MCP 工具），但不会自动接群消息。**

### 2. 如果能成为渠道

那 `qoder.communication` 会拉起 `dist/worker.mjs`，一切按设计工作——这一点已经用模拟宿主验证通过（消息投递、回复回传全跑通）。

### 3. 会话归属

渠道创建的会话归渠道所有，**不能接管你在 Qoder 里手工创建的会话**。首次 @ 时自动建，之后复用。

### 4. 卸载

卸载插件会清理 `QODER_CHANNEL_DATA` 下的配置，围炉侧不受影响。

## 如果要让它真正可用

**唯一的路是上架 Qoder 市场**（Qoder 官方回答里明确说了）。步骤：

1. 按本插件结构做好 `campfire-channel`
2. 联系 Qoder 官方谈上架（Qoder 应用内「问题反馈」/ qoder.cn / qoder.com）
3. 说明：协议 v4 已存在、`wecom-channel` 是先例、围炉是自托管群聊中枢

**上架后**用户从市场装，pluginId 就是 `campfire-channel@qoder-marketplace`，渠道发现能正常走通。
